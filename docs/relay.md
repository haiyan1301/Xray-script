# 出站中转与手工配置边界

中转入口为「9. 管理配置 → 2. 分流管理 → 7. 出站中转」。可粘贴脚本分享链接导入节点，也可手动填写 SOCKS5 或 VLESS + REALITY TCP 节点；保存多个节点，每次启用一个。节点列表和应用确认不显示密码、UUID、REALITY 公钥等凭据。

分享链接解析与 UDP 测试使用 Python 3；脚本安装器会检查并安装 `python3`、`util-linux`（操作锁）及 `coreutils`（超时控制）依赖。

### 分享链接导入范围

导入时选择添加/导入节点，粘贴一条分享链接，检查脱敏后的名称、地址、端口和协议，再保存并选择策略。导入只解析链接，不访问链接中的 Web 地址，不执行其内容；敏感链接从标准输入传给解析器，不放入命令行参数。导入节点可改名或用新链接替换。

| 脚本节点 | 支持的出站组合 |
| --- | --- |
| Vision | VLESS + raw/TCP + REALITY |
| XHTTP | VLESS + XHTTP + REALITY，保留 path、mode、SNI、加密等参数 |
| Trojan | Trojan + XHTTP + REALITY |
| mKCP | VLESS + mKCP + `security=none` |
| HY2 | Hysteria2 + TLS |
| SS2022 | Shadowsocks 2022 密码套件 |
| 手动填写 | SOCKS5，或 VLESS + REALITY TCP |

CDN 和 Fallback 不是本次承诺的导入场景。独立分享链接只描述连接参数，无法可靠推断它来自独立 XHTTP 还是某个 Fallback/CDN 部署，解析器按实际协议组合校验；需要部署身份保证时应由操作者核对来源。未知协议组合、相互冲突或重复参数、格式损坏的凭据会被拒绝，避免丢掉参数后看似成功地导入。

其中 CDN 的 VLESS `security=tls`、WebSocket/gRPC、拆分下载设置和 HY2 跳过证书验证等组合不在导入范围。VLESS mKCP 使用 `security=none` 时还受核心版本安全约束：测试使用的 Xray 26.10.21 拒绝向公网 IP 建立未启用 VLESS 加密的该类出站；B 需启用相应 VLESS 加密，或使用适合该部署的私网地址，不能把链接解析成功当作核心必然接受。

导入节点允许 IP 和域名地址。域名在启用/重建时以超时限制解析，检查全部解析地址是否指回本机 Xray 监听端口后，向当前候选配置写入一个实际 IP；原域名及 TLS/REALITY SNI 保存在节点状态中。解析失败会中止此次应用，DNS 地址变更需要重新应用或重建才能生效。未启用的已保存节点不依赖实时 DNS 可用性。手动填写的节点地址使用 IP 字面量。

## 出口选择

| 策略 | 命中中转的连接 | 未命中的连接 |
| --- | --- | --- |
| 全流量 | 脚本业务代理入站的 TCP、UDP、直接目标 IP 连接 | API、防偷、反向代理、虚拟局域网按各自专用规则处理 |
| 按域名 | 客户端目标域名或嗅探域名命中清单 | 原有 WARP 规则，然后默认直连 |
| 关闭 | 无 | 原有屏蔽、WARP、直连规则 |

专用规则、所有屏蔽规则优先于中转，中转优先于 WARP。`direct` 保持第一出站，避免没有匹配规则的系统流量误走 B。全流量规则限定实际业务入站标签，包含多节点编号标签与 Fallback 的内部代理入站，不包含 API、防偷、LAN、反向代理入口。

`example.com` 规范化为 `domain:example.com`，包括其子域名；`full:api.example.net` 只匹配该域名。输入接受逗号或换行，去空白、转小写、去重；不接受 URL、端口、通配符和正则表达式。国际化域名请先转为 ASCII/Punycode。

域名分流只对可获得域名的连接生效。IP 连接没有可识别的 HTTP Host、TLS SNI 或 QUIC 域名时走未命中策略。启用 ECH、非 HTTP/TLS 协议、应用绕开代理的 DNS、缓存连接均可能影响观察结果。`routeOnly: true` 让嗅探只决定路由，保留客户端原目标地址。此功能不会让客户端本地 DNS 自动经过 B；需要根据客户端的 DNS 策略单独确认 DNS 出口。

## 手动修改 Xray JSON 后会怎样

脚本状态通常位于 `~/.xray-script/config.json`，运行配置通常位于 `/usr/local/etc/xray/config.json`。前者记录中转节点及策略，后者由模板和脚本状态生成。直接修改运行 JSON 不会自动导入节点和策略。

旧实现从模板重建运行配置，会删除手动新增的出站，而已保存路由可能仍引用被删除的标签；手动改变出站顺序还会改变默认出口。仅检查 JSON 语法无法发现这些问题，`xray run -test` 也无法证明规则顺序符合使用者意图。

本次实现采取以下保护：

1. 在脚本状态保存路由相关配置的规范化 SHA-256 快照，包含完整出站、路由、反向代理模块，以及入口标签、监听、嗅探、Fallback 等关系。对象字段顺序和 JSON 缩进不影响比较；出站和规则数组顺序影响比较。
2. 重建前比较磁盘运行配置与已验证快照。手工新增、修改、删除出站，修改路由或相关入口后，本次重建会停止，原运行 JSON 保留。不会自动删除自定义节点、重新排序规则或把手工设置冒充为脚本管理状态。
3. 旧配置没有快照时，先无副作用地生成旧脚本状态应有的配置进行比对；无法验证或与磁盘不一致则停止。首次安装、没有旧运行配置时允许正常生成。
4. 候选配置检查标签唯一性、路由出站/入站/负载均衡引用，以及出站代理链的缺失引用和循环。随后交给 Xray 核心进行真实配置校验，再成对提交脚本状态和运行 JSON。
5. 同时执行的脚本写入由锁串行处理；提交前再次比较磁盘文件内容，缩小生成期间另一个编辑器修改 JSON 后被覆盖的风险窗口。外部编辑器不会遵守脚本锁，最后一次比较与文件替换之间仍有短暂竞态；请先结束手工编辑，再执行脚本。重启失败时恢复原配置并重启旧服务。

遇到「检测到手动修改」时，按以下步骤处理：

1. 停止其他编辑和脚本操作，把两份 JSON 分别复制到权限为 `700` 的备份目录，备份文件设为 `600`；其中可能包含账号、密码和私钥。
2. 核对手工出站、规则、代理链、负载均衡及标签引用。保留手工配置的部署应继续由其配置管理方式维护，脚本不会强行接管这些配置。
3. 要恢复脚本管理，优先恢复手改之前、与当前脚本状态相配的运行 JSON 备份。若脚本状态也改过，须恢复同一时点的两份备份；不要把不同时点的节点状态与运行配置拼在一起。没有匹配备份时先根据脚本状态逐项核对配置，不要删除自定义出站来尝试绕过检查。
4. 对准备恢复的 JSON 执行 `xray run -test -c /path/to/restored.json`，验证通过后保留正确文件权限地替换运行文件，再重试原脚本操作。Xray 核心校验通过不代表它与快照一致，脚本会继续做路由比较。

删除快照字段不能跳过检查，旧配置仍需通过生成结果比对。快照是防误操作机制，不能防止同时修改脚本状态与快照的操作者。

日志设置和入站认证信息不属于路由快照；仅改它们不触发路由漂移，但这些运行 JSON 手工变更也不会自动持久化到脚本状态，之后重建仍按脚本状态生成。应使用脚本提供的配置入口维护受管设置。

## 计划之外需要注意的场景

| 场景 | 处理与限制 |
| --- | --- |
| B 断线、凭据错误、UDP 不通 | 命中中转的连接报错，不静默降级到直连或 WARP。切换节点或关闭中转才能改变出口。 |
| SOCKS5 只支持 TCP | TCP 成功不能代表 UDP 成功；需检查 B 的 UDP ASSOCIATE、UDP 防火墙和地址可达性。 |
| Vision 与 UDP 443 | `flow` 影响 UDP 443，普通 UDP 测试成功不能证明 QUIC 可用；需针对实际流量验证。 |
| 中转目标指回本机 | 校验本机地址和 Xray 监听端口以阻止明显回环；云平台公网回流、NAT 映射和其他主机的相互中转仍需人工排查。 |
| IPv6 节点 | 节点状态中地址不带方括号，分享 URI 中 IPv6 地址按 URI 语法用方括号；A 必须具有可用 IPv6 路由。 |
| 改协议、更新、重启 | 已保存节点与策略继承，并按新生成的实际业务入站标签重建，不复用旧标签。 |
| 明确重置路由 | 关闭中转并清空域名，节点清单保留，避免重置后隐藏策略继续生效。 |
| 删除活动节点 | 先关闭中转或切换到其他节点；不允许保存悬空的活动引用。 |
| 手工使用保留标签 | `xray-script-relay-*` 出站与 `xray-script-relay` 路由标签由脚本管理，不应用于手工扩展。 |
| 已建立连接 | 改策略会重启 Xray，已有连接可能中断。节点测试只能说明测试时刻和测试目标的可达性。 |

## 验证

自动回归入口：

```bash
python3 -m unittest discover -s tests -v
python3 tests/check_core_configs.py --xray /path/to/xray --smoke
```

新增回归覆盖输入、域名规范化、所有现有协议模板、Fallback 和多节点标签、规则优先级、重复应用、关闭清理、悬空引用/循环、旧配置迁移、手工配置漂移、重启失败回滚、域名解析和并发文件修改。核心矩阵新增 14 个中转场景，合计 45 组配置由官方 Xray 26.10.21 校验并在临时端口启动，包含 WARP、反向代理、LAN、多节点、Fallback 和两种 CDN 后端。该测试不访问远端 B。

核心配置校验和本机测试无法替代 A、B 两台真实服务器的出口验证：应分别验证 TCP、UDP、UDP 443、目标 IP、根域名/子域名/精确域名、屏蔽规则、WARP、B 掉线，以及域名缺失时的策略。
